# ABAI Mockup · мокапы процессов Upstream

Кликабельные прототипы и пошаговые презентации целевых процессов на продуктах ABAI.
Для каждого процесса — три варианта из BPMN: **AS IS**, **TO BE Nedra** и **Dream TO BE** (целевой вариант на ABAI).
Чистый HTML/CSS/JS без сборки: открывается из файла и публикуется на GitHub Pages как есть.

Сайт: https://znewk.github.io/abai-mockup/

## Общий движок `shared/proc/`

Геология, Разработка и Бурение собраны на одном движке: `shared/proc/model.js` (данные BPMN, сопоставление шагов
вариантов по коду и названию, метрики), `app.js` (главная, рабочее место, процесс, схемы, сравнение), `app.css` + `proc.css`,
`charts.js`; презентация — `shared/proc/v2/` (`ui.js` — хелперы экранов, `present.js` — движок, `v2.css`).
В модуле остаются только `js/config.js` (MODULE, варианты, справочник систем, роли, метаданные процессов),
`js/dash.js` (рабочие места и мини-экраны шагов) и `v2/js/slides.js` (сценарии). Добыча и Освоение — на своих исходных движках.

Главная (`index.html`) — портал со всеми модулями и схема «Модули, продукты и потоки данных в цифровом двойнике»
(AS IS / TO BE Nedra / Dream TO BE): пользователи → процессы модулей → ЦД (пласта, скважины, добычи и наземной
инфраструктуры) → слой данных → зона ДЗО, внешние системы через интеграции. Архитектура TO BE — по стратсессии
(слайд 54, соответствие продуктов Nedra ↔ ABAI — слайд 34), системы процессов — из BPMN: `shared/landscape-data.js`
генерирует `node tools/build_landscape.js` (запускать после обновления `bpmn-data.js` любого модуля),
отрисовка — `shared/landscape.js` + `landscape.css`.
Потоки данных — `shared/landscape-flows.js` (ведётся вручную, у каждой связи указан шаг BPMN или слайд): сценарии по видам
(«Суточная добыча», «Отклонение → мероприятие», «Подбор ГНО», «Геомодель → точки бурения» …). Выбранный сценарий рисуется
компактной схемой «откуда → что → куда» над архитектурой, наведение на систему показывает все её потоки: система — полоса посередине, источники снизу, получатели сверху, у каждой связи своя прямая стрелка.
По встрече по ЦД 01.10 на портале также: блок «Что даёт ЦД» (эффективность ГТМ, добыча, экономика —
с привязкой к процессам), уровни доступа пользователей, число систем в шагах BPMN и рамка «Производственные системы ДЗО»
(HSE: электронный наряд-допуск — предварительно модуль ABAI, TUMAR; ТКРС: электронный заказ-наряд ПРС/КРС; транспорт: ИС УТО —
«Управление поездками») по пресс-релизам КМГ и сценарий потоков «Производственные системы» — только известные связи
(публикации КМГ, встреча по ЦД, BPMN Б5).
Кнопка **«Вся сеть»** — все системы и связи вида на одной схеме без всплывающих окон: ряды как на большой схеме (снизу вверх),
ортогональные стрелки по дорожкам между рядами, на стрелке — номер; наведение на номер или систему подсвечивает связи,
клик по номеру раскрывает связь в списке под схемой (там же шаги BPMN). Одинаковые «откуда → куда» из разных сценариев объединены.
У каждой связи — «кто»: исполнители шагов BPMN (дорожка и организация: КМГ, КМГИ, КазНИПИ, ОМГ, НГДУ, подрядчик), под сценарием —
блок «Кто что делает» по организациям и ролям.
Два режима просмотра потоков — **Простой** (что передаётся) и **Подробный**: по каждой связи — как передаётся, формат
(если указан в документах шага BPMN) и шаги BPMN «откуда / куда» с исполнителем, системами, документами и аннотациями.
Клик по системе открывает центральное окно и сайдбар справа (Esc — закрыть). В центре три режима:
**Путь данных** — откуда данные приходят в систему и куда уходят дальше через промежуточные системы, по сценариям потоков
(«Все сценарии» — не дальше двух передач в каждую сторону), с проигрыванием по этапам; клик по системе на пути — её путь;
**Связи системы** — все её связи на схеме в натуральную величину; **История по шагам** — каждый шаг BPMN, где указана система:
внизу шаг «до» и связи, по которым система получает данные, посередине сам шаг (исполнитель, системы, аннотации, документы),
вверху шаг «после» и связи, по которым она передаёт данные. В сайдбаре — список всех шагов BPMN системы (с соседними шагами
«до / после») и связей на схеме; клик по шагу — показать его в центре. Под схемой шага в «Истории по шагам» — **слайд презентации** с экранами ролей на этом шаге (встроен, все действия сразу; шага нет в быстром сценарии — ближайший слайд процесса и ссылка на шаг в прототипе), у шагов и связей — ссылки «слайд ↗» (только Dream TO BE: презентации построены по нему). Привязка шага к слайду — по номерам шагов в `code` слайда, считает `build_landscape.js` (сообщает шаги без слайда). Слайд и шаги синхронны в обе стороны: листаете шаги — слайд встаёт на действие шага (`/a3` в конце адреса — открыть слайд на 3-м действии), листаете слайд — презентация сообщает порталу (`postMessage`) слайд и действие, сверху открывается шаг этого действия; привязка шага к действию — по «Шаг 6.4а: …» в описании действия. `/full` в конце адреса — все действия слайда сразу. Заголовки верхнего уровня схемы (ЦД пласта, скважины, добычи, ЦД Актива, бизнес-модули, слой данных, зона ДЗО, внешние системы, пользователи) кликабельны — окно **«что это»** по стратсессии (`LS_BLOCKS`: что это, где применяется, цикл работы с моделью и роли, модули ABAI и что они делают, внедрение — с номерами слайдов; сокращения; системы блока и его связи со схемой). Этапы плашки под схемой пронумерованы и на самой схеме (номер — на блоке этапа). Под схемой в каждом режиме — блок **«О системе»**: что это (описания из справочников систем модулей — `ABAI_SYS_DESC` в `landscape-data.js`), откуда и как берёт данные и что отдаёт дальше (со ссылками на шаги и слайды), по процессам BPMN (что делает — аннотации шагов о системе; что получает и отдаёт), по сценариям потоков (что даёт сценарий; клик — его путь данных) и реестр задействованных систем и инструментов (в общих шагах BPMN и в связях схемы; клик — окно системы). Все вертикальные схемы читаются снизу вверх
(ось «откуда ↑ куда» слева). Шаги для истории — `shared/landscape-trail.js` (все шаги BPMN по видам, подгружается при первом
открытии), генерирует `node tools/build_landscape.js`.
Шаги для подробного режима — `shared/landscape-steps.js`, генерирует `node tools/build_landscape.js`
(запускать после правки `landscape-flows.js` и `bpmn-data.js`; генератор сообщает о ссылках на несуществующие шаги). Dream TO BE — по аннотациям
шагов («берутся из…», «поступают в…»), AS IS и TO BE Nedra — по последовательности шагов и документам (там, где способ передачи
в BPMN не указан, связь помечена серой). В шапке каждого приложения есть переключатель модулей
(`shared/modules.js`): новый модуль добавляется одной записью в `ABAI_MODULES`.
Старый адрес презентации «Освоения» (`/v2/`) переадресует на `osvoenie/v2/`.

**Десктоп или веб.** У систем на схеме портала и на дереве ЦД Актива — значок: монитор — десктоп (устанавливается на рабочее место), глобус — веб
(в браузере), оба — есть и то и другое. Справочник `LS_PLATFORM` в `shared/landscape-flows.js` (ведётся вручную): системы ABAI и КХД — веб, продукты Nedra и инженерное ПО — по сайтам
производителей; таблица (система, как работают, что именно) — под схемой портала («Десктоп или веб»), в корне дерева ЦД Актива и строкой
«Как с ним работают» в карточке модуля / в «О системе». Системы без записи в таблицах не выводятся, значка у них нет.

## Дерево ЦД Актива (`tree/index.html`)

Показ задумки «погружением» (Dream TO BE): **ЦД Актива на базе ABAI** → **единые данные** (сквозной слой) → на них — системы данных
(КХД, ABAI БД 2.0) и двойники по ходу производства: **ЦД пласта**, **ЦД скважины**, **ЦД добычи и наземной инфраструктуры** → модули ABAI (в скобках — продукт Nedra,
сл. 34) → процессы BPMN, где модуль используется → шаги (со слайдом презентации). Иерархия — по стратсессии: сл. 54 (ЦД и слой данных), сл. 14 (ИМА),
сл. 55–56 (дорожная карта ЦД Актива). На каждом уровне — **ветви обмена данными** с подробностью этого уровня: у ЦД Актива части и окружение
(зона ДЗО, внешние системы, пользователи) целиком, «туда и обратно» — одной двусторонней ветвью, между двойниками — синхронизация моделей ИМА (сл. 14,
серым: способ передачи не описан); у части — её модули (у единых данных — КХД и БД 2.0) отдельно, остальное целиком; у модуля, процесса и шага — каждая
система отдельно и каждое направление со шагами BPMN. Под схемой — список ветвей (номер на стрелке = номер в списке, наведение подсвечивает),
связи внутри свёрнутых узлов — счётчиком «видны при погружении». Клик по узлу схемы — погрузиться в него. Те же ветви рисуются **на верхнем дереве**: дерево само раскрывает ветки, куда данные уходят
и откуда приходят, — у ЦД Актива к частям, у части и модуля к модулям, у процесса и шага к тому же процессу и шагу BPMN в ветке другой системы
(«Р1 1.10 → 1.11»: отдаёт на 1.10, принимает на 1.11); своя система — тем процессом / шагом, где записан обмен. Стрелки ортогональные: у каждой своя вертикальная дорожка в коридоре между колонками (коридор шире по числу дорожек), точки крепления на узле разведены по порядку другого конца, узел с множеством связей выше; ближе к узлам — связи внутри колонки и между колонками, дальше — к «Вне ЦД»; линии иерархии при этом бледнее. Системы вне ЦД (зона ДЗО,
внешние, пользователи) — плашками колонки «Вне ЦД», к узлам не из последней колонки — по дорожке над деревом. Номер на стрелке = номер в списке,
наведение подсвечивает ветвь и на дереве, и на схеме; «Скрыть обмен данными» убирает ветви и с дерева. «Далее / Назад» (← →) идут по частям и
модулям, на кнопке — куда. Файлы: `shared/twin.js`, `shared/twin.css` (дерево и карточки — классы `tree.css`, схема ветвей — `lsNet` из `landscape.js`
с параметрами `info` / `order`).

Внизу карточки модуля, процесса и шага — **схема BPMN процесса (Dream TO BE)** из того же `bpmn-data.js`, что вкладка «Схемы BPMN» прототипа
(подгружается в скрытом iframe — у модулей одинаковое имя переменной `BPMN`): шаги модуля выделены, текущий шаг — жёлтой рамкой, клик по шагу —
открыть его в дереве; у модуля — вкладки по его процессам; масштаб и ссылка «схема в прототипе».

**Режим «Сценарии ЦД»** (переключатель в шапке; основной режим — «Дерево ЦД»): сценарии потоков данных Dream TO BE (`LS_FLOWS`, те же, что на портале).
Выбранный сценарий раскрывает на дереве полную цепочку: каждый конец передачи — шаг BPMN процесса из ссылки связи в ветке системы
(«Р1 1.10 → 1.11»: отдаёт на 1.10, принимает на 1.11), без шага — процесс или модуль; системы вне ЦД — плашки, связи между ними — дугами справа.
Стрелки пронумерованы по ходу сценария; «Далее / Назад» и ← → проигрывают цепочку по шагам (текущая передача подсвечена, дерево прокручивается к ней;
описание: что передаётся, вид связи, кто, шаги BPMN и слайды, «в дереве ↘» — открыть конец в режиме дерева; под описанием — **экран ABAI**: встроенный слайд
презентации на действии шага-получателя или шага-источника). В карточке процесса — экран первого шага модуля, у которого есть слайд. Ниже — список передач и схема BPMN
процессов сценария (вкладками, выделены шаги сценария). Адрес — `#sc/<сценарий>/<шаг>`.

## Подробное дерево ЦД (`tree/full.html`)

Последовательный показ архитектуры ЦД от верхнего уровня вглубь (ссылка — над схемой на портале):
вид (AS IS / TO BE Nedra / Dream TO BE) → **слои по этапам** (1 сбор → 2 КХД → 3 БД ABAI → 4 ЦД на базе ABAI → 5 решения по ролям, снизу вверх)
→ **блоки** (ЦД пласта, скважины, добычи, слой данных, зона ДЗО …) → **системы** → **процессы BPMN** → **шаги** → **системы шага** → их процессы …
Отдельная ветка — «Процессы модулей (BPMN)»: модуль → процесс → шаги → системы. Элемент, уже встречавшийся выше, в цепочке показывается снова —
так видна полная цепочка каждого процесса. На каждом уровне: что это (для блоков — по стратсессии, со слайдами), откуда и какие данные получает,
куда передаёт, кто пользуется (исполнители шагов BPMN по организациям) и как (процессы); у системы — путь данных и «О системе», у процесса — полная
цепочка шагов, у шага — до / после, системы с аннотациями, связи и слайд презентации. Сверху — само дерево схемой: колонки уровней слева направо, линии от родителя к детям, выбранная ветка подсвечена; под ним — карточка узла
(данные блока и слоя — схемой: посередине рамка блока с его частями и системами, снизу источники, сверху получатели; каждая связь —
своя стрелка прямо в систему внутри блока или из неё, на подписи — куда именно («→ в ABAI ЦРНС 2.0 · ЦД пласта»), что, кто и шаг BPMN; подробности свёрнуты).
У слоя, блока и системы в дереве — ветки **«⬇ Откуда данные»** и **«⬆ Куда данные»**: внешние источники / получатели по связям схемы
(у каждого — что передаёт); их можно раскрывать дальше и так пройти цепочку данных; системы на схемах карточки кликабельны — открываются в дереве.
У шага — ветка **«➜ Дальше по процессу»** по стрелкам BPMN: следующие шаги (у развилки — с условием), переход в смежный процесс
(если он есть в мокапе — его узлом) или **«■ Конец процесса»** с итогом из BPMN; клик по системе, из которой пришли, возвращает к ней.
«Далее / Назад» (← →) идут по дереву по порядку до выбранной глубины (до блоков / систем / процессов / шагов); у каждого узла свой адрес. Принадлежность систем к блокам берётся
со скрытой большой схемы портала. Файлы: `tree/full.html`, `shared/tree.js`, `shared/tree.css` (механики и данные — `shared/landscape*`).

## Геология

- **Процессы:** Г1 контракт на недропользование и разведку, Г3 доразведка, Г3.1 полевые СРР, Г3.2 обработка
  сейсмики, Г3.3 интерпретация сейсмики, Г3.4 геологическая модель.
- **Варианты:** пулы в BPMN без имён — вариант берётся из аннотации над пулом. AS IS — as is KMGD, есть AS IS Nedra,
  TO BE Nedra (в Г1 и Г3 помечен в BPMN «не отрисована / не заполнена», в Г3.2–Г3.4 его нет), Dream TO BE — итоговый
  «to be KMGD» с легендой ИС. Промежуточный «to be KMGD» без легенды пропускается. В Г1 Dream перенумерован — шаги
  сопоставляются с AS IS по названию.
- **Метрика:** шаги, которые выполняются в ABAI (AS IS → Dream TO BE).

## Разработка

- **Процессы:** Р1 выбор системы разработки, Р2 программа ГТМ, Р3 среднесрочный профиль добычи, Р4 оптимизация ППД,
  Р5 моделирование пласта.
- **Варианты:** AS IS — «фактическое использование модулей ИС ABAI», TO BE Недра, Dream TO BE. Для Р5 в BPMN есть только
  AS IS и TO BE Недра — экраны Р5 построены по AS IS и это показано на каждой вкладке.
- **Модули ABAI** из записей вида «ИС ABAI (ЦРНС, УЗ, Petrel)»: УЗ 2.0 — «Управление заводнением 2.0» (стратсессия, слайд 34).

## Бурение

- **Процессы:** Б1 проектирование скважин, Б2 подготовка к бурению (программа, МТР, ВМР), Б3 мониторинг бурения
  (РВД, отклонения, отчётность), Б4 освоение, Б5 планирование и контроль бригад ВСР.
- **Четыре варианта в каждом BPMN:** AS IS Nedra, AS IS (детальный, as is KMGD — основа Dream TO BE), TO BE Nedra, Dream TO BE.
  Сравнение шагов идёт по детальному AS IS; ручная работа — документы Excel / Word / PDF и согласования в рабочем чате.
- **Прототип:** как в «Добыче» — главная с картой связей Б1 → Б2 → Б3 → Б4, рабочие места, процесс Dream TO BE,
  схемы всех четырёх вариантов, сравнение. Для Б4 есть ссылка на подробный модуль «Освоение».
- **Презентация:** быстрый сценарий на каждый процесс (`burenie/v2/#b3/1/all`).

## Освоение скважин

- **Прототип:** реестр, «Мои задачи», цифровое дело скважины (10 шагов + 4.4.1–4.4.4), подписание ЭЦП через
  NCA Layer (имитация), возврат на доработку, SCADA → ABAI ТР, сравнение в ТР 2.0, страница AS IS → Dream TO BE.
  Для прохода с нуля — скв. 7412, кнопка «Сбросить демо» в реестре.
- **Презентация:** быстрый сценарий и «Возврат на доработку», карта сценария со стрелками последовательности.

## Добыча

- **Источник:** итоговые BPMN АО «Озенмунайгаз» (`TO BE/Добыча_омг_финал`). Прежняя версия по ЭМГ (`TO BE/Добыча`)
  в модуле больше не используется.
- **Четыре варианта в каждом BPMN:** AS IS Nedra, AS IS ABAI (как сейчас, с текущими модулями ABAI — с ним сравнивается
  Dream TO BE), TO BE Nedra, Dream TO BE. Метрика — шаги в ABAI и привязки шагов к MS Office.
- **Прототип:** главная с 9 процессами и картой связей между ними; для каждого процесса — рабочее место
  ключевой роли, пошаговый процесс Dream TO BE с переключением ролей, схемы BPMN всех четырёх вариантов
  (отрисованы по координатам из файлов) и сравнение систем по шагам.
- **Презентация:** быстрый сценарий на каждый процесс — карта «роли × шаги» и слайды с экранами ролей.
  Процесс выбирается вверху, роль — переключателем.

Шаги, дорожки, системы и аннотации генерируются из BPMN (`tools/` лежит рядом с репозиторием, в папке с BPMN):

```bash
python tools/extract_bpmn.py abai-mockup/dobycha/js/bpmn-data.js "TO BE/Добыча_омг_финал"
python tools/extract_bpmn.py abai-mockup/burenie/js/bpmn-data.js "TO BE/Бурение"
python tools/extract_bpmn.py abai-mockup/geologiya/js/bpmn-data.js "TO BE/Геология"
python tools/extract_bpmn.py abai-mockup/razrabotka/js/bpmn-data.js "TO BE/Разработка"
```

После обновления BPMN достаточно перезапустить генератор — схемы, шаги и сравнение пересоберутся.
Рабочие места и сценарии презентации написаны вручную: `<модуль>/js/dash.js`, `<модуль>/v2/js/slides.js`.

## Управление презентациями

`→` / пробел — следующее действие, `←` — назад, `F` — полный экран.
Ссылка на конкретный слайд: `osvoenie/v2/#fast/3/contractor`, `dobycha/v2/#d6/3/sngdu`, `burenie/v2/#b2/3/po`, `geologiya/v2/#g31/3/omg`, `razrabotka/v2/#r4/2/kaz`.

## Запуск локально

Откройте `index.html` или поднимите сервер: `python -m http.server 8000`.
Состояние прототипов хранится в `localStorage` браузера.

Все данные демонстрационные: скважины, показатели, ФИО вымышлены.
